## 产品设计想法 + 整体设计方案（画布定稿，未改代码）

用户问「对于产品设计还有什么好的想法」，先给诊断再给方案；随后「按照你的想法开始去整体设计」，
理解为**整体设计定稿**（画布视觉方案），不是直接改代码。确认后再按 ①→④ 落地。

### 产品诊断（三条结构问题）
1. 播放器长成了博物馆：「找歌→放歌」与「记录→回看」两条线挤在首页，导航按功能而非意图组织。
2. 回顾页全是只读展柜：墙能点播单曲、年鉴能存 PNG，但没有「把这段时间重听一遍」的路径。
3. 首周真空 + 好功能被时间锁住：四张回顾卡同时空；「反画像抽曲」只在 0–5 点深夜出现，白天进不去。
   （已核实：`taste.js` 的 `bootstrap()` 启动时会自动建同步码，记录本身没有门槛，问题在首周数据空。）

### 方案要点
- 信息架构从「按功能分页」改为「按时间分层」：今天（主导区）/ 听 / 回看三段；
  **所有回看动作只有一个出口：加入播放队列**。
- ① 回听闭环：墙「重播这一天」、年鉴「把这一期做成歌单」、首页「去年今天」；
  统一队列带来源角标，不新建歌单实体。四条规则：空态给动作 / 按真实播放顺序 / 同曲去重标 ×8 / 沿用现有跳过兜底。
- ② 30 天像素热度条：越亮听得越多，点方块跳到那天的墙。
- ③ 今日一曲：每天只出一首，画像 + 近 30 天没播过，播过盖「已听」章；「意外的」搬到白天。
- ④ 体感：⌘K 像素终端命令面板、成就解锁即时反馈（音效+菜单栏闪+toast）、深夜手动开关与可撤销提示、
  不可播标具体原因（VIP/版权/未登录）、五种系统状态清单。
- 明确取舍：不再加独立展柜页、不做 AI 文案与外链分享、首页坚持不铺满、一屏尽听降为次级。

### 画布踩坑（重要，下次直接避开）
- Ardot 的 SVG frame 里颜色**不能写 `%23RRGGBB`**（data-URI 编码），会被解析成非法颜色回退成纯黑：
  像素音符、8 段电平、墙格暖光、热度条三档、进度格全部变黑，「越亮越多」这类信息直接丢失。
  改用 `rgb(r,g,b)` 最稳，`stroke` 同理，半透明用 `fill-opacity`。
- `U(node, {svg: ...})` 不会重新解析矢量子节点，必须 `D(旧节点)` + 重新 `I(..., {svg})`。
- text 里的 `▶` 会被判 emoji 并报 potentialIssues，改用 `PLAY` 等纯文字或矢量图形。
- 画板用 `layout:"none"` + 子节点绝对坐标最省事；先插背景块再插文字，避免层级遮挡。

### 核查
两轮截图：第一轮发现 SVG 颜色全黑 → 一次性重建 9 个矢量图形；第二轮确认琥珀暖光/三档热度/
3-of-8 进度均恢复，四张画板无溢出、无重叠、无文字裁切。年鉴小报柱图保留黑墨柱（奶油底上像印刷，可读性更好）。

## v2 改造落地（按设计稿实现，版本 1.2.0）

### 数据与接口
- 新增 `app/modules/replay.js`：纯事件流运算，不依赖平台。`buildReplay / buildHeat / buildLastYear / pickDaily`。
  时间口径统一走 `event-time.js` 的 `timeOf(e)`（真实发生时间 `clientTs`/`ts`），避免离线补报污染当天与去年同日。
- `app/server.js` 注册 `/api/taste/{replay,heat,lastyear,daily}`；**无同步码时按空库返回，不甩 400**（首周空态原则）。
  `dailyCache` 只缓存检索结果，`heard` 每次按当天事件流重算 —— 「已听」不新增持久化状态。
- 今日一曲用 `dayHash(day)` 保证当天稳定；固定 `DAILY_LINES` 短文案，不做生成式 AI；
  并行检索 + `withTimeout(3500)` 防断网连续等待；曲库无结果时从一年内、近 30 天没播过的老记录兜底。

### 统一队列（回听闭环的核心）
- `window.EW.replay(params,label)` 是**唯一出口**：墙「重播这一天」/ 年鉴「把这一期做成歌单」/
  首页「去年今天」/ 今日一曲全部汇入 `EW.play(list,0)`，不新建歌单实体。
- 事件流只存歌曲基础信息 → `resolveReplayTracks()` 后台批量补 QQ `mid`、XY `epid`、缺失 `id`，
  用 `queueGen` 防止旧回放任务污染新队列，不打断当前播放。
- 队列显示 `.src-tag.from` 来源角标与重复次数；不可播沿用「直接下一首」，
  `classifyWhy()` 给出 VIP 限制 / 版权下架 / 音源未登录 / 加载失败。
  **坑**：`playIndex()` 的 catch 原来把错误信息裁到 18 字并删括号，导致「VIP 或版权歌曲需登录」被截成泛化文本，
  改为保留完整 `err.message` 后分类才生效。
